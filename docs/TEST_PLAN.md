# ESP32-C3 + ML307 回归测试计划

本文档用于每次发布前重复验证固件。默认串口为 `/dev/ttyACM0`，目标为 ESP32-C3，工具链固定为 ESP-IDF v5.5.2。

## 1. 不破坏数据的准备

1. 记录当前 IP、Wi-Fi 配置数和短信箱数量。
2. 备份完整 4 MB Flash，另行保存 SHA-256。
3. 单独备份 NVS（0x9000，0x5000 字节），以便访问方式测试后恢复现场配置。
4. 仅烧录应用分区；不执行 `erase-flash`，不覆盖 NVS 和 `sms_data`。

## 2. 构建和静态检查

| 项目 | 操作 | 通过标准 |
|---|---|---|
| 主机回归 | `bash tests/host/run.sh` | 安全策略、CID 解析、PDU 和门户 DNS 全部通过 |
| 完整构建 | `idf.py build` | 无错误，镜像未超过 app 分区 |
| 前端语法 | 抽取页面 `<script>` 并用 Node.js 检查 | 无 JavaScript 语法错误 |
| 代码清洁度 | `git diff --check` | 无空白或补丁格式错误 |

## 3. 默认免密与可选认证

1. 使用新装 NVS 或未启用密码的现有 NVS 启动。
2. `GET /api/session` 必须返回 `auth_enabled=false`、`authenticated=true` 和 CSRF 令牌。
3. 刷新管理页必须直接进入管理中心，不显示登录或首次设置。
4. 配网门户在免密状态下必须直接显示 Wi-Fi 扫描与配网页。
5. 写接口仍必须要求会话 Cookie 和正确 CSRF，缺少任一项返回 401。
6. 在“设置 → 访问安全”启用密码：短于 10 位、两次不一致必须拒绝；保存后刷新必须显示登录。
7. 错误密码必须返回 401，正确密码可进入；关闭密码保护后再次刷新应恢复直接访问。

## 4. ML307 与 CID 1 安全策略

1. 连续执行 3 次 ESP32 冷启动，保存启动日志。
2. 启动阶段用单层有界重试查询 `AT+CGACT?`；仅返回 `OK` 且没有上下文行时按 CID 1 未激活处理。
3. 最终状态必须为 `modem_ready=true` 和 `packet_data_disabled=true`。
4. 诊断页执行 `AT+MIPCALL?` 和 `AT+CGACT?`：第 1 路应用拨号必须断开，CID 1 必须为 0；CID 8 允许由模组维护，不影响通过结果。
5. 分别执行软重启和硬重启，任务必须结束为成功，且再次核验 CID 1。
6. 仅当完整有界重试仍无法确认 CID 1 已关闭时，才应拉低 EN 并暂停短信。

## 5. Wi-Fi 与门户

1. 读取现有配置，确认最多 3 组且密码不会由 API 返回。
2. 添加一组测试 SSID，修改后删除，其他历史网络不受影响。
3. 连接成功的网络必须成为首选；重启后应自动回连并保持 IP 可访问。
4. 无可用网络达 3 分钟后，必须开启恢复热点，同时继续尝试历史网络。
5. 门户扫描列出附近 2.4 GHz Wi-Fi，成功连接后显示实际后台 IP 并自动跳转。

## 6. 短信箱、发送与通知

1. 启动前后对比短信 ID 和内容，最近 10 条必须保留。
2. 发送一条专用测试短信到设备，确认实时入箱；重启后仍存在。
3. 删除该测试短信，确认刷新和重启后均不再出现。
4. 经用户确认目标号码和费用后，从后台发送中文短信，任务状态必须成功，收件端内容正确。
5. 对每个已配置的 SMTP/推送通道使用测试短信验证投递；未配置外部凭据时标记为“未执行”，不伪造通过结果。

## 7. 页面与故障恢复

1. 在手机竖屏、横屏和桌面宽度检查首页、短信、诊断、通知、设置五个页面，不得溢出。
2. 所有写接口在缺少/错误 CSRF 时必须返回 401。
3. 重启 ESP32 后验证 Wi-Fi、访问方式、通道、短信箱全部持久化。
4. 核对最终固件 SHA-256，并将分区镜像、合并镜像和校验文件一起发布。
